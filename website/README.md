# 工百窗宣传网站

独立静态宣传页，入口为 `index.html`。

官网的定位是**30 秒决策页**：让人在扫读中知道「这是什么、什么时候用」，然后愿意点开短片或直接下载。它不承担讲完整个故事——来历留给长文，版本事实留给 Release，官网只负责让人愿意继续。

## 页面结构

| 区块 | 任务 |
|---|---|
| Hero | 一句话 + 两个动作：下载 / 看它工作 |
| `#film` | 「六十秒，看它怎么消失。」主位是 60 秒短片；短片到位前由可点的交互示意承担同一任务 |
| `#idea` | 设计初衷：唤出 → 衔接 → 归还，各配一句叙事副标 |
| `#possibilities` | 四张卡，每张只讲一个动作级场景 |
| `#manifesto` | 边界声明：它不是平台 |
| `#ownership` | 东西在你自己的电脑上 |
| `#download` | 版本、架构、校验、系统要求 |
| FAQ | 五个真问题 |
| 页脚 | **全站唯一**写维护期限的地方：一句承诺，不写结局 |

维护期限只在页脚出现一次，写成「会维护到 2029 年 9 月 3 日」。不写「之后会退场」这类结局叙事——那是运营层面的事，不是官网该说的话。

## 本地预览

在仓库根目录运行：

```powershell
npx --no-install vite website --host 127.0.0.1 --port 4173
```

打开 http://127.0.0.1:4173 。也可直接用浏览器打开 `website/index.html`，无需安装新依赖或构建桌面程序。

## 发布

把整个 `website/` 目录放到任意静态网站托管服务，保留 `assets/` 相对路径即可。页面不依赖外部字体、CDN、API 或构建步骤。下载按钮指向项目 GitHub 发布页，避免硬编码会过期的版本和安装包地址。

## 页面维护

- `index.html`：文案与结构。**每次改文案前先确认它属于官网，而不是长文或 Release。**
- `styles.css`：排版、响应式断点（1600 / 1100 / 800 / 560）、窗口示意与减少动态效果偏好。文件保持纯 ASCII，避免编码问题；勾号等符号用 CSS 转义写（如 `\2713`）。
- `main.js`：移动导航、四个工作区标签、唤出/收起演示，以及短片播放按钮（`[data-film]`，无素材时不生效）。标签支持方向键、Home、End；菜单支持 Escape。
- `assets/icon.png`：从现有应用图标缩小生成，保留产品品牌。

## 插入 60 秒短片

`#film` 区块内有一段 HTML 注释，写明替换方式。把注释里的 `desktop-demo` 换成 `film-frame` 结构即可：封面按钮 + `preload="none"` 的视频 + 字幕轨。**不要给视频加 `autoplay`**，播放完全交给 `main.js`，否则「无 JS 时退化为静帧」的承诺不成立。

## 不要写进官网的内容

- 来历故事（属于长文）、版本号与版本事实（属于 Release）
- 「功能丰富」「上限极高」「重磅」「史诗级」等词
- 结局叙事（「之后会停」之类）；维护期限只在页脚说一次
- 尚未做出来的功能，或「即将支持」类预告
- **不存在的快捷键或功能**：写之前对照 `electron/hotkey/store.ts` 与当前版本实测，不要沿用旧版文档

保留本地保存与第三方 AI 服务数据处理的说明，避免将本地资料存储描述成远程 AI 完全离线。交互示意不提供真实 AI 服务。
