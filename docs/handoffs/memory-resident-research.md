# 驻留内存优化：公开实现对照

> 2026-10-17新增：[三张截图、当前实例原生构成与Mem Reduct固定版本源码核对](memory-working-set-explanation-2026-10-17.md)。当前只读样本私有驻留121MiB、总工作集227MiB、私有提交1458MiB，进一步说明这些指标应并列，清理瞬间值与常态、提交与驻留不能混用。

2026-10-16。目标保持：标准态刚启动整树低于300MiB；持续使用时降低驻留且保持输入、呼出体验。窗口退役条件和时长以现有代码为准。

## 已查阅的一手资料

- Mem Reduct源码：https://github.com/henrypp/memreduct/blob/master/src/main.c 。使用NtSetSystemInformation清理工作集、文件缓存、modified/standby列表。系统级清理会影响其他应用；本产品只回收自身进程，不直接移植全系统清理。
- Microsoft SetProcessWorkingSetSizeEx：https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-setprocessworkingsetsizeex 。工作集是物理驻留页；软最大值允许充足内存下增长。硬最大值会改变换页行为，不适合用来强压活跃界面。
- Edge sleeping tabs：https://blogs.windows.com/msedgedev/2022/04/07/sleeping-tabs-edge-100/ 。闲置标签休眠，点击恢复；官方平均每个休眠标签节省85%内存、99%CPU，属于其测试结果，不能套用到本产品或活跃标签。
- Electron性能指南：https://www.electronjs.org/docs/latest/tutorial/performance 。减少启动加载和不必要工作，避免主进程阻塞。

## 本轮采用

1. 复用已有Windows启动辅助程序承载前台桥，去掉常驻PowerShell的额外运行时。
2. 采用自身进程、身份校验、空闲保护的工作集清空（SetProcessWorkingSetSizeEx的最小/最大值均为-1）。高低内存机器都允许后续空闲回收；低内存机器更早评估，成功或回涨后延长间隔。没有持续硬上限，也不清空全系统缓存。
3. 回收快速回涨时有上限地延长冷却，后续仍可重试。已删除单次耗时超过10ms、或累计三次回涨后永久停止该进程回收的规则。超过100ms的原生调用至少等待2分钟后重试；无明显收益的调用等待15分钟。成功后仅在整树进入对应窗口数量的内部余量范围时逐步减少频率。
4. 记录整树工作集和私有提交量；普通PageFaults不是硬缺页，不能据此宣称磁盘换页无卡顿。

## 验收界限

一次清理后的最低值不能替代启动峰值，也不能证明长期稳定。真实默认网页、持续输入/滚动/呼出、低内存机器仍必须分别验证。公开资料已获取，未成功获取的Chromium源文件不作为证据。

## 2026-10-17 持续回收调度修正

每5秒评估一次，空闲时最多串行清理4个本软件进程；每个进程前重查应用输入、保护任务和开关，150ms后不再启动本批下一次调用。此时间约束不打断已经提交的原生系统调用。保留启动20秒、常态30秒、低内存15秒的空闲要求及CPU保护，不销毁网页，不调整退役时间。

原生层先确认调用方父进程及根进程身份。最近的系统输入只有在前台属于本应用进程树时才阻止清理；用户在其他软件里操作不再让隐藏的SidekickAI一直无法回收。应用自身的输入、加载、下载、导入、音视频和捕获仍由JS侧保护。无法检查前台进程身份时保守跳过。

清理成功后的首次冷却为60秒；低收益/慢调用/快速回涨均有限退避，PID+创建时间换代后不继承旧进程状态。原生临时跳过仅保留30秒尝试间隔，不消费成功回收的长冷却。

在扩大批次前补齐应用任务保护：自定义AI流式回答、素材导入、备份导出/恢复、网页及API原件传输也会暂停回收。它们不一定表现为webContents.isLoading或持续高CPU，不能只依赖网页加载状态推断。

只在开发者选项保留一个默认关闭的低内存模式开关。自动回收启用/禁用分别采样，报告保留整树工作集、私有提交、启动样本、后半段中位数/P95、回收次数和网页/界面会话标记。MEASURED仅说明测量及交互检查有效，所有内存上限单独判定。

## 正常绘帧后的持续活跃负载

去掉日常收起中的minimize后，短测不再稳定复现停帧，但300秒禁用回收组仍出现过原生可见而主界面hidden的偶发失败，不能认定根治。正常绘帧基线中，2px标签指示条的无限呼吸动画使GPU持续约单核9.5%活跃，主界面约2.1%；不能依赖此前停帧后的低工作集判断体验达标。低内存模式改用静态主题色高亮，关闭开关即恢复原动画；不停止网页动画、媒体或输入，不关闭后台节流。

主进程空闲维护约单核0.6%，此前0.5%的CPU门槛会使其一直无法回收。经隔离对照将近空闲界限改为单核1%，所有20/30/15秒的输入空闲要求、原生输入复核、加载和业务保护继续生效。120秒实验后半段中位数262.3MiB、P95 274.5MiB，两次正常唤出双rAF为36/41ms，证据local/resident-ab-6uQpiK；不足以证明启动300MiB或长期体验达标。后续以正式构建更长对照为准。


2026-10-17沙箱候选：主界面与网页预加载各自自包含打包，窗口工厂默认及will-attach-webview改为sandbox=true。仅保留Electron支持的预加载API，编译时拒绝残留Node模块及相对外部require。短测已核实renderer sandboxed=true与原生事件注入后的点击/实际滚动。正式等时长测仍按独立开关组执行，具体证据见内存报告。语音预览和WindowManager的独立webPreferences暂仍保留原配置，本轮没有据此声称所有进程都已迁移。

后台renderer独立空闲已接入候选：同一PID的全部webContents必须归属同一未聚焦窗口；窗口中任一guest输入同时保护壳和兄弟renderer。每PID调用前重新检查归属、活动与任务保护，原生层再核对顶层HWND属于根进程、不是当前前台或前台popup的root-owner。主进程/GPU/网络、跨窗共享及归属不明renderer仍要求全应用空闲；20/30/15秒阈值、音视频/捕获/加载/业务保护及退役规则不变。

持续输入短测local/resident-ab-188fln/report.json（120秒/组，无CDP）有效：每组115次固定前台输入脉冲、119次mouseMove确认，20次逐窗点击/实际滚动/草稿/身份/双rAF均通过。29次成功回收全部为后台Tab，不含持续输入窗口壳/guest或共享进程。active-input-audit.json核对每次回收前的采样：最久全局输入空闲仅1028ms，采样到调用最长54ms；不是等待前台停止操作后才清理。后半段工作集中位数3498.3→1904.7MiB，末次私有提交1724.5→1738.5MiB。收益主要是物理驻留，不能当作实际分配下降。300秒/组长测仍需独立判断；短测不代表真实AI网页或全部三态目标达标。

300秒/组持续输入长测local/resident-ab-LgrvnA有效：后半段中位数3465.2→1821.8MiB、P95 3657.5→2018.3MiB，35次后台Tab回收。每组60次点击/滚动/草稿/身份/双rAF均通过，所有回收距全局最近输入最多730ms。私有提交1879.3→1927.0MiB；原GPU提交异常仍需分别分析，不能据新一轮未出现相同幅度异常认定已修复。

追加保护：监控在第一窗加载前安装，按Electron的media-started-playing/media-paused计数，补上静音视频；renderer退出清除计数，单个媒体暂停不释放其余播放保护。真实双视频local/resident-media-W2Dhcs在完全静音且无捕获时，双播放30秒、单播放20秒均无回收；全部暂停后计数清零并恢复3次回收，页面/草稿保留。此追加修改的完整verify为195文件/1557测试，桌面数据及加密备份恢复联调s4CoRp通过。持续输入候选复测单独记录，不将追加前的长测混作同一构建结果。

## 缩短功能联调等待与减少辅助进程

按用户要求先运行功能短测，稳定后按需要执行持续验收。原型最小宿主默认5秒待机；标准交互30秒；新增回收流程最多45秒，实际完成即退出。回收流程仍走正式策略和原生二次输入检查，保留生产20/30/15秒空闲、冷却、热键防连触发及退役资格/期限；缩短诊断轮询和测试总时长。FUNCTIONAL_PASS明确不证明持续内存容量通过。

原生桥通过detached启动及UTF8标准流去掉conhost，父进程EOF仍退出。实际默认页短测local/resident-ab-3sCR5d的15条整树样本全部包含SidekickStartup.exe，均无conhost；旧候选曾约7.5MiB的控制台占用不能直接当作本轮严格A/B收益。该短测回收次数0，因此增设空闲后恢复的专门流程，不能在持续输入中一再短测后误认为自动回收链路已验证。

原生RegisterHotKey轻宿主原型338.892秒/61样本峰值33.406MiB，符合原型70MiB容量。实际退出/保存/唤醒/失败恢复已联调；产品admission及安装器尚未支持宿主身份，不能据原型宣布产品最小态完成。当前标准态启动仍约888MiB，300MiB目标继续失败。完整数据及实现边界分别见内存报告和minimum-host-integration.md。

新回收短测暴露标准态5个Electron进程超过原单批4个上限，用户再次输入前网络进程常未获清理。现改为最多8个，150ms批次预算和每进程前活动重查不变。原生助手仅在全局空闲请求成功后顺带清空自身工作集，原生输入再次复核，自身回收最少间隔60秒且仅对16MiB以上驻留生效；独立后台renderer请求不回收共享助手。真实短测J7pXfY中5个目标完成、助手降至1.859MiB、网络进程9.484MiB，呼出后整树236.629MiB、双rAF32/51ms，私有提交531.434MiB，启动893.352MiB仍FAIL。不能从驻留下降推断实际分配或启动峰值通过。

45秒十浏览器功能联调QcAnrx：20次成功回收全部为后台Tab，固定前台42次输入/44次确认，10次点击/滚动/草稿/身份/双rAF均通过；共享助手保持23.35–24.41MiB，未触发全局空闲自身清理。整树峰值4227.398MiB、末次2144.875MiB，本地短测容量PASS，26个采样身份退出无残留。完整回归195文件1559测试通过。长测证据继续保留，不能把这次短测扩大为长期或真实AI页结论。
