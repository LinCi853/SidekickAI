# 窗口三状态设计与验收（2026-10-16）

> 2026-10-17 交付状态：本文件保留目标与验收口径，不代表目标全部达成。最小宿主试验已移除，正式产品保留低内存模式的自身进程驻留回收；标准态含启动峰值低于 300 MiB 仍未达成。源码清理与 x64 打包见[本次交付记录](memory-cleanup-release-2026-10-17.md)。

本文件统一三态验收。刚启动即标准态，整个应用进程树必须严格小于 300 MiB；旧 1240 MB 目标与放宽退役建议不再适用。可见未聚焦窗口退役、退役时间、保护与恢复全部以当前代码为准。

## 状态契约

| 状态 | 驻留与功能 | 整树内存目标 |
|---|---|---|
| 最小态 | 只保留快捷键唤出入口，完整主窗及网页不常驻 | 严格小于 70 MiB |
| 标准态 | 一个完整主窗实例，随时呼出/收起，操作不受限制 | 刚启动及标准态整树严格小于 300 MiB |
| 极限态：非浏览器 | 十个真实主窗实例，尚未进入浏览器页面 | 不超过 1 GiB |
| 极限态：浏览器 | 十窗均进入浏览器状态，每窗至少一个就绪网页 | 不超过 5 GiB，游戏模式另测 |

收起不等于进入最小态。标准态热呼出不得重建窗口或重载网页，但不取消既有退役和休眠期限。隐藏释放十分钟、整体后台释放三十分钟；退役映射及实际登记资格读 electron/shared/background-policy.ts、electron/window/window-retirement.ts 与各调用点，不能据旧提示词改时间。

口径为构建/打包态指定根 PID 的全部后代进程总工作集，含共享页、主进程、GPU、网络及所有 renderer。共享页按每进程求和不去重。暂沿用仓库 MiB/GiB，保留原始字节。专用工作集、显存、提交内存和仅 Tab 合计不可混用。

用户已授权在低内存模式中持续清空本软件空闲进程工作集，机制见 memory-resident-research.md。该开关默认关闭，启用/禁用分别验收。清理后的低值不能替代刚启动样本、持续回涨、真实交互及实际私有提交；完整主窗即使瞬间工作集低于70MiB，也不属于只保留快捷键的最小态。

标准态候选指标：已注册快捷键回调到渲染层可见不超过 200ms；这是工程建议，不是用户已定数值。真实键盘路由、首帧及所有操作另测 P50/P95/最大值。

## 设计修改

1. 最小态尚未实现。application-main.ts 启动创建完整主窗，hotkey-ipc.ts 在主窗不存在时直接返回。推荐原生 Windows 轻量宿主，仅驻留 RegisterHotKey、启动路径与激活会话，复用 edition-session 单例协议。宿主和启动的应用均计入进程树，不能产生未计量孤儿进程；先实测驻留/激活原型再接入产品。
2. 标准态复用焦点服务、持久化和单例；日常收起保留热态，最小态到标准态的冷启动耗时单列。完整应用退出前完成落盘，播放/下载/导入保护按既有代码执行。
3. 十个非浏览器主窗缺明确生产入口。先实现真实多实例壳与进入浏览器动作，复用配置、preload、公共资源并隔离状态。合成空窗、聊天窗、独立网页不能冒充十主窗验收。
4. 十浏览器已有生产 detach 入口，但 GPU/壳峰值接近上限。一次 GPU 工作集 1864 MiB 后回落至 1169 MiB；256MB GPU 参数不是进程总工作集硬上限。优先检查最大化建窗再还原的纹理峰值和公共资源重复加载，同尺寸、同网页、十页不卸载对比。
5. 网页预算监控仍用于网页压力，不代替整树验收。不能为达上限卸载每窗唯一可用页。游戏豁免依据真实模式状态，不全局免检。
