## 当前可运行的原型

`tools/minimum-host/MinimumHost.cs` 使用 .NET Framework 与 Win32 `RegisterHotKey`、消息循环，独立于 Electron。只接受真实父进程的 PID、FILETIME 创建时间、同会话和同一启动映像；启动时和每次唤醒前核对应用文件 SHA256。参数逐项校验并按 Windows argv 规则转义。控制管道仅当前 SID/SYSTEM 可访问，使用随机 nonce、长度和读取期限限制。

原应用仍存活时收到唤醒，只记待处理请求。原应用退出后先让出快捷键，再启动同一 exe。只有实际启动子进程的 PID 和 FILETIME 同时匹配才接受 ready 并退出宿主。应用在 ready 前退出，或 Process.Start 失败，则恢复快捷键；注册冲突有限频率重试。正常成功与失败准备阶段有明确状态，不能用上一轮错误判断当前尝试已经结束。

优先运行 `npm run test:minimum-host`：仅等待5秒待机，输出 FUNCTIONAL_PASS，验证退出、接管、失败恢复、持久化和唤醒。按用户最新要求，等待参数可在隔离测试中缩短，避免每次功能修改都重复长测；短测明确标记 capacityDiagnosticOnly，不能代替持续内存验收。需要持续验收时显式运行 `node scripts/verify-minimum-host.cjs --standby-seconds 300`。

构建器先执行磁盘预算清理，产物仅在 `build/native-minimum/`，不会复制进正式资源。测试使用独立 profile/session，两端加载真实 `out/main/index.cjs`，核对笔记、设置和生产快捷键持久化。首轮用管道验证退出前的待唤醒，第二轮通过 SendInput → WM_HOTKEY 唤醒。记录整个宿主树总工作集、私有提交和 CPU，检查原 Electron/助手残留。SendInput 和双 rAF 均不能替代物理键盘与屏幕首帧。

短测 `local/minimum-host-3yRqFg/report.json` PASS：13条整树样本，峰值31.3MiB，空闲CPU约单核0.065%；管道请求至冷启动主界面双rAF约2038ms，已启动后的生产快捷键回调至双rAF为124ms。后者不是最小态冷启动速度。长测独立记录在内存报告。

长测 `local/minimum-host-glvpqj/report.json` PASS：61条整树样本覆盖338.892秒；峰值33.406MiB、中位数31.969MiB，空闲CPU约单核0.046%。只有SidekickMinimum.exe常驻；原Electron及助手残留检查通过。工作集30.699→33.406MiB、私有提交22.320→24.793MiB，不能据5分钟结果认定长期无增长。SendInput至主界面双rAF为1130ms，暖回调至双rAF为120ms；真实默认网页可用性另测。产物归档SHA256：19e5b065974c7e3efd7b6c46d9a7b3bff500a7580154c0dd7dad6335b26ecee6。

快速入口 `local/minimum-host-3KxBic/report.json` FUNCTIONAL_PASS：6条诊断样本，31MiB以内；默认5秒待机流程完整通过。此时正式回收桥已换成无控制台管道候选，宿主实验仍未接入产品单例。

## 必须完成的产品交接

1. **应用所有权。** `reserveApplicationSession` 在持久化库之前抢占整个交互会话的 edition 管道。当前协议严格核实 PID 对应的产品 exe；原生宿主的 PID 对应另一 exe，不能把它伪装成产品进程，也不能绕过 verify。应增加明确的轻宿主身份，核实实际 helper 映像、受信任安装资源及对应产品路径/版本、SID、会话、FILETIME。
2. **同会话互斥。** 宿主待机必须持有同一 edition 协调入口。手动启动应唤醒/交接已有应用；同时启动、连续快捷键、跨版本与跨版本型不能产生两个数据所有者。唤醒子进程在打开数据库前需完成受验证的 admission 交接；最终 ready 与让出 admission 不是同一阶段。当前实验管道的 yield/stop 仅停止实验宿主，不能直接当作生产交接。
3. **安装器和恢复。** `NativeInventory.cs` 与 PowerShell fallback 当前只枚举两个产品 exe。必须让安装、卸载、版本切换和备份操作识别并协作关闭宿主。只依据文件名、命令行里的产品路径或客户端声称的 PID 不足以建立身份；强制处理也要重新核对实际进程创建时间和安装映像。
4. **进入最小态。** 复用现有保存/冻结/退出协议。保存拒绝、正在录音/播放/下载/导入/导出/流式回答、无可用呼出快捷键等情况保持完整应用并给出已有失败反馈。宿主成功注册且控制入口可用后才能提交退出；失败时恢复原快捷键与编辑器。不得把主窗口新增到现有退役登记，也不得改动10分钟/30分钟及各类窗口退役资格和时长。
5. **唤醒与开关。** 继续只在开发者选项保留默认关闭的一个低内存模式开关。日常隐藏仍是标准态热呼出；最小态明确属于完整应用退出后的冷启动。不得显示点击恢复或截图占位。保留持久化的主窗热键及禁用状态；不支持的组合不能静默替换为默认热键。
6. **权限。** 当前实测进程为 elevated。普通权限、低/高完整性之间的手动启动与安装交接仍需单独验证；管道 ACL 不能为方便而向其他账号开放。

## 产品验收缺口

宿主被正式识别前，现有 `verify-memory-states.mjs --state minimum` 仍是隐藏完整应用的失败基线，不应改成调用实验宿主后直接宣称产品 PASS。正式入口、安装器/单例、冷启动网页可用性、持久化窗口/账号资料、退出取消、权限变化、物理键盘和屏幕首帧均需覆盖。标准态启动300MiB、十非浏览器主窗1GiB以及真实AI负载的十浏览器5GiB继续独立验收。
